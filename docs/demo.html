tofu-drifttofu-drift

Find what changed behind your OpenTofu state’s back, and what’s running in AWS that no state knows about.

Reports Drift on OpenTofu/Terraform-managed AWS resources, plus Unmanaged and Idle resources with a $/mo and kgCO₂/mo estimate on each. AWS only, read-only, no backend.

brew install wardbox/tap/tofu-drift

Or go install github.com/wardbox/tofu-drift/cmd/tofu-drift@latest, or a binary from the releases page.

How it works

One Scan reads one state, one AWS account and one region. Nothing is written, locked or sent anywhere.

1 · Read
Your statewhat OpenTofu manages: tofu state pull, a file, or s3://
Live AWSwhat actually exists: list and describe calls across 25 resource types, read-only
→
2 · Compare
Three checks
  1. Changed? tofu plan -refresh-only diffs managed resources against AWS (inside a root module).
  2. In state? each AWS resource is looked up by its Match Key (instance ID, bucket name, ARN…).
  3. Used? unattached volume, unassociated Elastic IP, load balancer with zero targets, stopped database…
Children like an instance's root volume fold into their parent.
→
3 · Find
Driftmanaged, but changed outside OpenTofu
Unmanagedexists in AWS, in no state
+ $/mo · kgCO₂/mo
Idlecosting money, doing nothing, managed or not
+ $/mo · kgCO₂/mo
↓
One reporta table, --json, or --explain <id> for the working behind one row

What each finding means

Every row is one Finding for one resource. Its STATUS says which of these it carries.

Three kinds of Finding

Drift

A Managed Resource was changed outside OpenTofu: a console edit, a script, another tool. The provider reports it during a refresh-only plan; tofu-drift only renders it. Drift is never costed and never ignored.

Unmanaged

A live AWS resource whose ID or ARN appears in no scanned state. Someone made it by hand, or its state was lost. import-gen writes the import blocks to adopt it.

Idle

Provably unused by a structural rule, whether managed or not:

  • EBS volume unattached
  • Elastic IP unassociated
  • network interface unattached
  • ALB/NLB whose target groups are all empty; classic LB with no instances
  • EBS snapshot whose source volume is gone
  • AMI no live instance was launched from
  • RDS instance stopped

What stays out of the report

Default Furniture

What AWS creates in every account or VPC without being asked: the default VPC and its subnets, each VPC’s default security group and main route table, service-linked IAM roles, the default ECS cluster. Hidden unless you pass --include-defaults.

Derived Resources

Resources another resource created: an instance’s launch-time volumes, a NAT gateway’s Elastic IPs, an AMI’s snapshots, an Auto Scaling group’s instances. They never get a row. Their cost folds into the parent’s.

Ignore Rules

A tofu-drift.toml in the current directory drops matching Unmanaged and Idle rows by tag, type or ARN glob. Every field in one rule must match.

[[ignore]]
tag = "ManagedBy=other"

[[ignore]]
type = "aws_s3_bucket"

[[ignore]]
arn = "arn:aws:iam::*:role/legacy-*"

Quick start

  1. Run it inside an OpenTofu root module for the full report. State comes from tofu state pull, so any backend and the current workspace work. 
    cd path/to/root-module
tofu-drift scan
  2. Or point it at a state from anywhere. With --state there is no module to plan against, so Drift is skipped and you get Unmanaged and Idle only. 
    tofu-drift scan --state s3://<bucket>/<key>
tofu-drift scan --state terraform.tfstate
  3. Choose the account and region with the usual AWS profile and region, or override them. 
    tofu-drift scan --profile <profile> --region us-west-1
  4. Feed it to scripts or CI. --json works on every command. Exit code is 0 with no Findings, 1 with any, 2 on error. 
    tofu-drift scan --json > report.json
  5. Grant read-only access. iam-policy.json lists every AWS action a scan calls. Run without credentials and tofu-drift prints it and exits 2.
