tofu-drifttofu-drift

tells you what changed in aws outside of tofu, and what’s running in your account with no state behind it.

aws only. read-only, no backend, nothing to host. every stray resource gets a rough $/mo and kgCO₂/mo so you know what to kill first. works with opentofu and terraform state.

brew install wardbox/tap/tofu-drift

or go install github.com/wardbox/tofu-drift/cmd/tofu-drift@latest, or grab a binary from releases.

how it works

one scan looks at one state, one aws account and one region. it never writes, locks or sends anything.

1 · read
your statewhat tofu thinks exists. from tofu state pull, a file, or s3://
live awswhat exists right now. list and describe calls on 25 resource types
→
2 · compare
three checks
  1. changed? tofu plan -refresh-only diffs your managed stuff against aws. needs a root module
  2. in state? every aws resource gets looked up by id, bucket name or arn
  3. used? unattached volume, loose elastic ip, load balancer with no targets, stopped database
stuff one resource made for itself, like an instance's root volume, rolls up into the parent
→
3 · find
drifttofu manages it, someone changed it anyway
unmanagedin aws, in no state
+ $/mo · kgCO₂/mo
idlecosts money, does nothing. managed or not
+ $/mo · kgCO₂/mo
↓
one reporta table, --json, or --explain <id> to see the math on one row

wide tables scroll sideways. the NAT gateway’s elastic ip has no row of its own, its $3.65 is inside the NAT’s $38.69. the security group drift is a port 22 rule somebody added in the console.

what the rows mean

one row per resource. STATUS tells you which of these it hit.

three kinds

drift

tofu manages it and something changed it anyway. a console edit, a script, some other tool. the aws provider finds it during a refresh-only plan and tofu-drift prints it. drift never gets a price and ignore rules won’t hide it.

unmanaged

exists in aws, no state has its id or arn. somebody clicked it into existence or the state got lost. import-gen writes the import blocks to bring it under tofu.

idle

unused by one of these rules, managed or not

  • ebs volume not attached to anything
  • elastic ip not associated
  • network interface not attached
  • alb/nlb with empty target groups, classic lb with no instances
  • ebs snapshot, source volume deleted
  • ami nobody launched an instance from
  • rds instance stopped

what gets left out

aws defaults

stuff aws makes in every account or vpc without asking. the default vpc and its subnets, default security groups, main route tables, service-linked iam roles, the default ecs cluster. hidden unless you pass --include-defaults.

child resources

things another resource made for itself. an instance’s launch volumes, a NAT gateway’s elastic ips, an ami’s snapshots, an auto scaling group’s instances. no row of their own, the cost goes on the parent.

ignore rules

put a tofu-drift.toml where you run it to hide unmanaged and idle rows by tag, type or arn glob. a rule with more than one field needs all of them to match.

[[ignore]]
tag = "ManagedBy=other"

[[ignore]]
type = "aws_s3_bucket"

[[ignore]]
arn = "arn:aws:iam::*:role/legacy-*"

quick start

  1. run it in a tofu root module for the full report. state comes from tofu state pull, so whatever backend and workspace you’re on works. 
    cd path/to/root-module
tofu-drift scan
  2. or point it at a state file from anywhere. with --state there’s no module to plan against, so no drift. you get unmanaged and idle only. 
    tofu-drift scan --state s3://<bucket>/<key>
tofu-drift scan --state terraform.tfstate
  3. pick the account and region. it uses your normal aws profile and region unless you override them. 
    tofu-drift scan --profile <profile> --region us-west-1
  4. use it in scripts or CI. --json works on every command. exit code 0 means nothing found, 1 means something, 2 means it broke. 
    tofu-drift scan --json > report.json
  5. give it read-only access. iam-policy.json lists every aws call a scan makes. run it with no credentials and it prints the policy and exits 2.
